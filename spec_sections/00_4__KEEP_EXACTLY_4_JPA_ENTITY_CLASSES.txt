# 4. KEEP EXACTLY 4 JPA ENTITY CLASSES



Use exactly these primary entities.



## Entity 1 — Candidate



Represents the authenticated user/candidate.



Suggested fields:



```text

id

name

email

passwordHash

headline

location

education

experienceYears

targetRoles

resumeFileName

resumeText

createdAt

updatedAt

```



Do NOT create a separate Resume entity.



The extracted resume text can be stored directly in Candidate.



This intentionally keeps the entity count at four.



---



## Entity 2 — Opportunity



Represents anything the candidate may want to pursue.



Fields:



```text

id

title

organization

type

roleFamily

description

location

workMode

url

deadline

postedAt

active

createdAt

updatedAt

```



`type`:



```text

JOB

INTERNSHIP

HACKATHON

CTF

OTHER

```



`roleFamily` should remain a flexible text field rather than creating another entity.



Examples:



```text

Software Engineering

Backend Development

Frontend Development

Full Stack

Cloud

DevOps

SRE

AI

ML

NLP

Data Engineering

Data Science

Cybersecurity

QA/SDET

Mobile

Product Engineering

Technical Support

Solutions Engineering

Other

```



Do not hardcode these values into the frontend.



The user can enter them, and the AI can suggest them.



---



## Entity 3 — Skill



Fields:



```text

id

name

category

createdAt

```



Examples are NOT seeded into the application.



The user can create them.



AI may also extract candidate skills or opportunity skills.



Skill category is free text such as:



```text

Programming

Framework

Database

Cloud

AI

ML

DevOps

Testing

Security

Tool

Soft Skill

Other

```



---



## Entity 4 — Application



Connects a Candidate to an Opportunity.



Fields:



```text

id

candidate

opportunity

status

appliedAt

nextActionDate

notes

createdAt

updatedAt

```



Status:



```text

TO_APPLY

APPLIED

ASSESSMENT

INTERVIEW

SELECTED

REJECTED

WITHDRAWN

```



Important:



**TO_APPLY is the way the system represents an opportunity the candidate has saved but not yet applied to.**



This avoids creating a fifth entity.
